# Hook design

Reusable standards for hooks in this package.

- Keep public APIs small and explicit; export types from the root entry only when they are part of the supported surface.
- Stay SSR-safe: no `window` / `document` / `MutationObserver` / browser globals at module evaluation time; attach observers and listeners in effects.
- Stay StrictMode-safe: every subscription must clean up so remounts do not leave duplicate active listeners or observers.
- Prefer a ref for the latest callback so handler identity changes do not force listener/observer churn. Prefer a React 18-compatible latest-handler strategy; do not rely on APIs unavailable in React 18.
- For event listeners, read mutable values such as `ref.current` at event time when that matches the hook’s contract.
- For removal / mutation observers, capture the observed element instance when observation starts. Do not depend on `ref.current` still pointing at a removed node when the observer callback runs.
- Mutable React refs do not trigger renders. After imperative `ref.current` assignment, sync observation from a committed render (compare element identity, then schedule observation). Do not put `ref.current` in an effect dependency array and assume React tracks it.
- Prefer `useEffect` for observer/listener lifecycle and target synchronization. Use `useLayoutEffect` only when synchronous layout measurement or DOM mutation before paint is required. When `useLayoutEffect` is used in a React 18-compatible package, verify React 18 SSR behavior with a packed consumer (`npm run test:ssr:react18`).
- Keyboard listeners should match exact `event.key` values, keep latest filters/handlers without listener churn, resolve default `window` only inside effects, treat explicit `null` targets as “no listen”, and document passive-listener / editable-target limitations honestly.
- Prefer focused local implementation over speculative shared hooks (`useMutationObserver`, `useLatest`, …) until reuse is proven across multiple hooks. Public `useEventListener` exists as its own hook; do not refactor other hooks onto it until a separate, evidence-based phase.
- For typed event listeners: prefer native event-map overloads, keep latest handlers without churn, normalize event-name arrays, resolve default `window` only inside effects, treat explicit `null` as “no listen”, pass native `AddEventListenerOptions` (minus `enabled`), and document that evaluating `document`/`window` as call arguments is the consumer’s SSR responsibility.
- For long-press / pointer gestures: use Pointer Events only (`pointerdown` / `pointermove` / `pointerup` / `pointercancel`); track one active `pointerId`; snapshot delay/threshold/coordinates at pointerdown; attach temporary listeners to `element.ownerDocument`; use owning-window timers/`performance` when available; clear timers and temporary listeners on cancel, blur, disable, target change, and unmount; report maximum Euclidean distance; call `onRelease` only on matching `pointerup` (not cancel/cleanup); keep latest `handler` / `onRelease` without restarting the gesture; do not auto-suppress click; do not treat long press as the sole accessible action path.
- For typing-intent hooks (`useOnStartTyping`): listen on `document` `keydown` inside effects only; keep latest handler/validator/detector without listener churn; run editable detection before character validation; default to ASCII alphanumeric with Shift allowed and Ctrl/Alt/Meta/`repeat`/`isComposing` rejected; treat custom validators as full replacements (caller owns modifier/repeat/composition filtering); detect editables via owning-window constructors plus contentEditable IDL/attribute walking (including open shadow roots); treat nested `contenteditable="false"` as non-editable; never call `preventDefault`/`stopPropagation` so initial characters may reach a newly focused input; do not export internal validators.
- For media-device capability hooks (`useDevicesList`): detect support via `navigator.mediaDevices.enumerateDevices` without touching browser globals at module evaluation; keep enumeration and `getUserMedia` permission as separate capabilities; use generation IDs for async races and an operation counter for overlapping `isLoading`; stop every temporary track in `finally` and never store streams in React state; keep latest constraints/`onUpdated` without listener churn; prefer explicit user-triggered permission over automatic `requestPermissions`; treat `permissionGranted` as hook-local attempt state, not a full Permissions API.
- For viewport hit-testing hooks (`useElementByPoint`): prefer `document.elementFromPoint` for single-element mode and `document.elementsFromPoint` for `multiple: true` — they return different shapes (`Element | null` vs. a full topmost-first stack including ancestor containers up to `<html>`), so keep them behind a `multiple` discriminant rather than trying to unify them. Type the return value as the DOM `Element` interface (not `HTMLElement`), since SVG and other element subtypes are valid hits. Only read `x`/`y` as client (viewport) coordinates; do not accept or infer page/document coordinates. Batch lookups through the target document's own `defaultView.requestAnimationFrame` by default (an opt-in `sync` scheduler may bypass batching for callers that need an immediate result), guard every scheduled callback with a generation counter so stale frames from superseded coordinates or unmounted instances cannot apply, and cancel pending frames on coordinate/option changes, pause, disable, and unmount. Keep `pause()`/`resume()` and an imperative `update()` as separate, composable primitives: `pause()` freezes the current result and stops scheduling; `resume()` immediately re-runs the lookup with the latest known options; `update()` forces an immediate lookup for callers whose layout changed without any option changing, and is intentionally a no-op while paused (do not special-case it to un-pause). Never write to, clone, or otherwise mutate the returned element(s) — the hook is read-only. Support an optional `document` override resolved without touching global browser objects at module scope, so callers can hit-test inside another same-origin `Document` (for example an iframe's `contentDocument`) using that document's own coordinate space.
- For hover-tracking hooks (`useElementHover`): register native `mouseenter` / `mouseleave` directly on the resolved target — not bubbling `mouseover`/`mouseout`, pointer events, or React synthetic handlers. Moving between descendants must not toggle the boolean. Normalize non-finite/negative delays to zero, snapshot delay values at event time, and cancel opposite pending transitions (leave before delayed enter, re-enter before delayed leave). Use the owning window's timer APIs when available; guard timer callbacks with a generation counter; keep only one pending transition timer. Sync listeners after every commit from `ref.current` without reattaching when the target identity is unchanged. Target replacement or `null` resets hover immediately (no leave delay). Optional `triggerOnRemoval` may use a private `MutationObserver` patterned like `useOnElementRemoval` rather than composing that hook, to avoid duplicate target-sync effects. Do not treat touch or keyboard focus as hover. Type with `Element` (including SVG). Re-enabling does not infer pointer position.
- For direct-focus hooks (`useFocus`): register native `focus` / `blur` on the resolved target — not React synthetic handlers. `focused` follows `ownerDocument.activeElement === target` with optional `:focus-visible` filtering (conservative false when matching is unsupported). Descendant focus does not count. Expose stable `focus()` / `blur()` via `useCallback`; pass latest `preventScroll` to hook-initiated focus only; do not set state optimistically. `initialValue` focuses each new enabled target once after commit without stealing focus on unrelated rerenders. Disabling resets hook state without blurring the browser element. Target replacement resets state without auto-blurring the old target. Type with `HTMLElement | SVGElement`. Pair with `useFocusWithin` for container-level focus tracking; do not implement focus-within or focus traps in `useFocus`.
- For focus-within hooks (`useFocusWithin`): register native bubbling `focusin` / `focusout` on the resolved container — not React synthetic handlers or document-wide listeners. `focused` follows owning-document `activeElement` containment (target itself or descendant). On `focusout`, keep true when `relatedTarget` is inside; set false when outside; defer one microtask reconciliation when `relatedTarget` is null or non-node. Invalidate deferred reconciliation on `focusin`, disable, target replacement, and unmount via generation guards. Re-synchronize on same-target commits. Disabling resets hook state without blurring browser focus. Type with `Element` (including SVG). Do not move focus, trap focus, or expose which descendant is focused. DOM portals outside the subtree do not count.
- For infinite-scroll hooks (`useInfiniteScroll`): attach one passive `scroll` listener to the resolved `HTMLElement` / `Window` / `Document` target; read metrics from the element or `scrollingElement`; load when `distanceToEdge <= distance` for the configured direction; serialize loads; normalize rejections into `error`; remeasure after success via owning-window animation frame; stop auto-chaining when geometry makes no progress until scroll/resize/`check()`/`reset()`; keep latest `onLoadMore` / `canLoadMore` without listener churn; optional owning-window `ResizeObserver` without shipping a polyfill; do not abort consumer promises; do not mutate scroll position or item state on `reset()`.
- For mouse-coordinate hooks (`useMouse`): listen to passive `mousemove` / `dragover` (and optional touch events) on a resolved `Window` / `Document` / `HTMLElement` / `SVGElement` target; omitted target resolves to `window` inside effects while explicit `null` registers nothing; support `page` / `client` / `screen` / `movement` plus custom extractors; recalculate page coordinates on owning-window scroll from the last client position only after a usable coordinate has been recorded; keep latest extractor / `eventFilter` / `initialValue` / `resetOnTouchEnd` without listener churn; contain extractor and filter throws; ignore stale delayed `eventFilter` invocations after disable, target replacement, or unmount; do not call `preventDefault` / `stopPropagation`; do not draw overlays.
- For mouse-pressed hooks (`useMousePressed`): attach press-start listeners (`mousedown`, optional `touchstart`, optional `dragstart`) to the resolved target; attach temporary release listeners to the owning window only while a lifecycle is active (`mouseup`, `mouseleave`, `touchend`, `touchcancel`, `dragend`, `drop`); reuse existing `UseMouseSourceType`; call `onPressed` / `onReleased` only on native transitions; perform administrative resets without callbacks on disable, target replacement, or registration-relevant option changes; treat `mousedown` followed by `dragstart` as one lifecycle; keep multi-touch pressed until the final active touch ends; pass `capture` consistently to all hook-owned listeners; do not call `preventDefault`.
- For parallax hooks (`useParallax`): accept an element/SVG ref only; attach passive `mousemove` to the target and optional passive `deviceorientation` to the owning window; normalize mouse axes from `getBoundingClientRect()` around center (`roll`/`tilt` ≈ `-0.5…0.5`); normalize orientation from `gamma`/`beta` with screen-angle compensation (`0/90/180/270`); never call `requestPermission`; keep latest adjusters/`clamp` without listener churn; contain throwing or non-finite adjusters by preserving previous state; most recent valid source wins and API presence alone must not switch source; reset to centered mouse fallback on disable/target null/replacement; do not write CSS or schedule rAF by default.
- For scroll-tracking hooks (`useScroll`): attach one passive `scroll` listener to the resolved `HTMLElement` / `SVGElement` / `Window` / `Document` target; read metrics from the element or `scrollingElement`; expose `x`/`y`, `isScrolling`, `arrivedState`, and `directions`; optional leading/trailing `throttle` and `idle`-based `onStop` (effective idle = `idle + throttle`); configurable arrival `offset` margins with RTL horizontal mode detection (`ltr`/`negative`/`reverse`); stable imperative `measure()`, `scrollTo()`, `setX()`, and `setY()` (immediate `measure()` only when imperative `behavior` is `'auto'`); optional coalesced `MutationObserver` remeasure when `observe: true`; keep latest callbacks/options without listener churn; sync target identity after every commit without putting `ref.current` in effect deps; contain platform/read errors via optional `onError`; do not mutate consumer DOM, manage focus, or cancel smooth-scroll animations.
- For scroll-lock hooks (`useScrollLock`): apply inline `overflow: hidden` on the resolved style-capable element; track owners in a module-local `WeakMap` multi-owner registry and restore the exact prior inline overflow axes (overflow / overflow-x / overflow-y, including `!important` on the shorthand) only when the final owner releases; resolve `Window` / `Document` targets to the document scroll root; treat `isLocked` as requested state for this instance (not global lock truth); do not suppress scroll/`wheel`/`touchmove` events; do not implement a focus trap or modal primitive.
- For screen-capture hooks (`useDisplayMedia`): the hook itself owns the active stream (store in a ref, mirror to state) so it can stop every track exactly once, whether stopped locally, replaced by a newer `start()`, ended by the browser's own "Stop sharing" control, or cleared on unmount. Sync to browser-driven endings via each track's `ended` listener rather than polling `track.readyState`. Guard async races with a request-generation counter so a stale resolved/rejected request cannot stop or overwrite a newer stream, and guard stale `ended` events so a track from an already-replaced stream cannot clear the current one. Treat `enabled` as an advanced declarative activation signal layered over the imperative `start()`/`stop()` pair, not a replacement for it — document that real browsers may block a declarative call without a preceding user gesture.
- For user-media hooks (`useUserMedia`): own every stream returned by `getUserMedia` requests this instance started; prefer imperative `start()` from a user gesture with default `enabled: false`; treat `start()` as atomic replacement (keep the old stream if replacement fails) and `restart()` as stop-then-reacquire (idle on failure); deep-compare `constraints` for `autoSwitch` without a runtime dependency (normalize object key order, preserve array order, contain cyclic malformed input); keep `isActive` based on at least one live track; on track `ended`, remain active while another track is live and clear only when none remain; compose with `useDevicesList` at the consumer layer without coupling implementations; do not polyfill legacy callback `getUserMedia`.
- For WebSocket hooks (`useWebSocket`): own every socket the instance constructs; guard all native handlers and reconnect/heartbeat timers with a generation/ownership token so stale sockets cannot mutate status, data, callbacks, or retry state; treat explicit `close()`, unmount, and intentional replacement as non-reconnectable; preserve FIFO outbound buffers across automatic reconnect and clear them on explicit close, endpoint change, and unmount; compare URL/protocol snapshots semantically (not options-object identity); run application-level heartbeats only while open with non-overlapping interval+pong timers; compare heartbeat Blob responses by actual bytes asynchronously and guard pending comparisons with socket plus heartbeat-cycle identity so a late match cannot clear timeouts or revive a closed/replaced connection; define `autoClose` as `beforeunload` only — React unmount always releases ownership; never construct sockets during render or module evaluation; do not add automatic JSON, Socket.IO, SSE, or custom HTTP headers.
- For local-storage hooks (`useLocalStorage`) and session-storage hooks (`useSessionStorage`): share a private browser-storage engine; pass an explicit Storage-area reader (`readLocalStorageArea` / `readSessionStorageArea`) so tree-shaking can drop the unused Storage property; access storage only in effects; first client render must match SSR (`defaultValue`, `isReady: false`, `isSupported: false`); never use `useLayoutEffect`; guard pre-ready `setValue`/`remove`/`reset` with pending-mutation ownership so late initialization cannot overwrite newer consumer intent; keep serializers/merge/error/registry semantics identical across both hooks; same-document sync uses a private WeakMap registry keyed by actual Storage object + key; `listenToStorageChanges: false` disables registry + native events; do not describe session storage as durable cross-tab global state (native session events apply only to eligible related browsing contexts); never store secrets in examples; Storybook keys must be namespaced and cleaned between play tests.
- For cookie hooks (`useCookies`): cookies are not Web Storage — keep a dedicated private parser/registry/observer under `useCookies/`; never expose `HttpOnly`; deletion requires matching path/domain; `set` success means assignment did not throw (canonical reread decides visibility); registry is keyed by `Document`; prefer Cookie Store `change` events when available and share one polling fallback per document (smallest positive interval); guard stale document generations; SSR reads require explicit `initialCookies` (response `Set-Cookie` stays the server’s job); Storybook cookie names must be valid tokens (no `:`), isolated, and cleaned with matching path; never use real secrets in examples.
- For progress indicator hooks (`useNProgress`): implement a package-native, zero-dependency progress bar; use a module-local `WeakMap<Document, Map<HTMLElement, ProgressChannel>>` registry for shared ownership keyed by `(document, parent)` pair and remove empty channels from the parent map so parents are not retained indefinitely; aggregate progress as the minimum across all active owners; presentation options (color, speed, etc.) come from the most recently updated active owner; create DOM via `document.createElement` (never `innerHTML`) using namespaced `data-react-hooks-nprogress-*` attributes; keep the decorative peg inside the bar so tip glow tracks progress (never as a full-width sibling near the spinner); inject at most one shared namespaced `<style>` per document for keyframes/reduced-motion and apply per-channel color/height/easing/position via element styles (never interpolate uncontrolled values into shared stylesheet text); include `prefers-reduced-motion` media query; keep the bar `position:fixed` for `document.body` and `position:absolute` for custom parents without modifying parent styles; generation-guard all completion timers; cancel stale timers on restart/re-acquire and reset `start()` during completion (`progress === 1`) back to `minimum`; never use `useLayoutEffect`; return `{ isLoading: false, progress: null }` during SSR with no-op methods; support declarative `currentProgress` parameter (undefined=imperative, null=complete, number<1=set, number≥1=complete, NaN/Infinity=ignored; number→undefined stops declarative sync without removing the owner); use a `completingRef` to prevent re-triggering `completeOwner` on every re-render during completion phase; allow `removeDelay: 0` (don't normalize zero to fallback for removeDelay); prevent zero-delay loops by rejecting zero for `speed` and `trickleSpeed`; trickle uses slowing-increment algorithm that never reaches 1 automatically; multiple owners share one timer per channel; `done(force=true)` briefly shows complete bar even when idle; `remove()` is immediate with no animation; `evictOwner` on unmount or context (doc/parent) change; keep methods stable via `useCallback`; document CSP style-injection limits and estimated trickle `aria-valuenow`; do not export private manager/helper symbols from `src/index.ts`.
- For JWT decode hooks (`useJwt`): decode compact JWS-style header/payload only — never verify signatures, authenticity, authorization, expiration, issuer, audience, or trust; keep Base64URL and UTF-8 parsing environment-independent (browser + SSR, no exclusive `atob`/`Buffer` dependency); keep decoding pure and synchronous during render/`useMemo`; invoke `onError` from an effect after a new error result; deduplicate effect-delivered parsing errors by both effective input generation (outer-trimmed token identity) and semantic error shape — not error shape alone — so Strict Mode replay and callback-identity changes do not duplicate while a newly supplied invalid token still notifies; never put full tokens in error messages, logs, DOM diagnostics, or snapshots; NumericDate `exp`/`nbf`/`iat` are seconds; generics do not validate runtime claim shapes; Storybook tokens must be synthetic and clearly marked; do not export private decoder helpers or a public encoder; never authorize users from client-side decoded claims alone.
- For QR generation hooks (`useQRCode`): depend on the MIT `qrcode` package as an intentional runtime dependency (externalize it in the library build; do not hand-roll an encoder or add a second QR library); keep package-owned public types instead of re-exporting `@types/qrcode` namespaces; preserve text exactly (no trim); treat `''` as idle and `' '` as valid content; default `enabled: true`, `errorCorrectionLevel: 'M'`, `margin: 4`; SSR/initial idle `{ dataUrl: '', isLoading: false, error: null }` with no encoder work during render; use generation IDs so newest automatic/manual request wins; clear prior `dataUrl` when a new owned request starts; validate options before calling the encoder (own properties only) and fail closed with normalized `Error` + latest `onError`; keep invalid option signatures distinct when values differ even if messages match; resolve dynamic `import('qrcode')` whether `toDataURL` is named or under `default`; keep `generate()` stable and usable while disabled, returning its own successful data URL even when stale for React state; never expose private helpers or third-party encoder types; document that scanning does not trust content, capacity depends on version/ECC, quiet zone/contrast matter, data URLs may be large, and there is no scanner/logo overlay/download manager; Storybook payloads must be synthetic/fictional only.
- For document-head favicon hooks (`useFavicon`): keep `icon` controlled by React state/props with no internal setter; default `enabled: true`, `rel: 'icon'`, `restoreOnUnmount: true`; resolve URLs with `new URL(icon, baseUrl ?? document.baseURI)` without trimming the icon string; treat `null`/`undefined`/`''` as release (empty string is intentional release; whitespace-only goes through URL errors); never fall back when `document: null` is explicit; match relations by inspecting `<link>` token sets (never build a CSS selector from consumer `rel`); prefer the last matching link; snapshot and restore exact managed attributes; use a private `WeakMap<Document, Map<relKey, channel>>` so most-recently-updated owners win, equivalent same-URL updates do not reorder/rewrite, and documents/relations stay isolated; apply `restoreOnUnmount` to unmount cleanup only with a generation-guarded deferred persist microtask (explicit disable/null/document/`rel` changes restore normally); roll back failed acquires so phantom owners cannot remain; never use `useLayoutEffect` or a continuous `MutationObserver`; reconcile external removal on the next relevant update without resurrecting removed originals; SSR idle `{ href: null, isSupported: false, error: null }`; do not add head-management libraries, favicon generators, badge drawing, image resizing, cache-busting, or manifest/Apple icon generation; document browser caching delays and that consumers own in-page accessible status.
- For native EyeDropper hooks (`useEyeDropper`): never open automatically — call `open()` only from a direct user gesture so transient user activation is preserved; invoke `new EyeDropper().open()` synchronously in the consumer `open()` call stack before any `await`, timer, effect, or preliminary promise; default `initialValue: ''`, `enabled: true`, `treatAbortAsError: false`; seed `initialValue` once (six-digit `#rrggbb` only; reject `#rgb`; invalid → `''` without render-time `onError`); normalize successful colors to lowercase opaque sRGB with no alpha; detect support structurally without constructing during render; omitted `window` resolves after mount while explicit `null` never falls back; own each attempt with a generation ID plus an internal `AbortController` when available (prefer the effective window’s constructor) and bridge external `AbortSignal` without mutating the consumer controller; when no usable controller exists still call native `open()` without a signal and let `cancel()` invalidate local ownership (native UI may remain open); newest `open()` owns state/`onError` while stale successes may still resolve their caller promise and stale failures/cancellations resolve `null`; aborts are normal by default; `reset()` restores latest initial value and clears error without cancelling an active picker unless documented otherwise; disable/window change/unmount invalidate active work without resetting the selected color on disable/window identity alone; validate native results via own-property `sRGBHex` checks; SSR idle unsupported with seeded `sRGBHex` and zero constructions; no polyfill, continuous sampling, element-only sampling, palette persistence, or permission preflight.
- For fullscreen hooks (`useFullscreen`): never enter automatically — call `enter()` / `toggle()` only from a direct user gesture so transient user activation is preserved; invoke native `requestFullscreen` synchronously before any `await`; prefer a coherent standard adapter then a coherent WebKit-prefixed adapter (request + exit + fullscreen-element state; do not mix families; incomplete standard yields to complete WebKit); sync from document change/error events as the source of truth; `isFullscreen` is true only when this instance’s target is the active element; `exit()` must not dismiss another element’s fullscreen; omitted ref uses `documentElement`, explicit null ref does not fall back; target `ownerDocument` is authoritative and mismatched explicit documents fail safely with a stable error (no commit loops); default `enabled: true`, `autoExit: false`, `navigationUI: 'auto'`; disabling detaches listeners without exiting platform fullscreen; `autoExit` best-effort exits on genuine unmount only (generation-owned deferred cleanup so Strict Mode remount does not exit; shared-target multi-instance unmount may exit); pending operations own `onError` once across error-event + rejected-promise pairs; target/document replacement rebinds observation without auto-exit; no CSS emulation, focus trap, Escape interception, orientation lock, or wake lock; SSR idle unsupported with commands resolving `false`.
- For URL search-parameter hooks (`useUrlSearchParams`): expose immutable `params` snapshots and defensive `searchParams` with explicit controls (no mutation Proxy); own one URL component per mode (`history` search, `hash` first-literal-`?` query with route preserved — `#foo=bar` without `?` is a route, `hash-params` entire hash with optional leading `?` stripped); write via `pushState`/`replaceState` preserving `history.state` by identity; never monkey-patch History or dispatch synthetic navigation events; sync same-window peers through a private WeakMap registry keyed by window+mode; rebase concurrent enabled writers onto the live URL while preserving never-written soft `initialValue` keys; merge `initialValue` only on bind/mode/window rebind/`reset()` — not on `refresh()`, peer sync, or navigation; failed History writes keep prior bound state; custom `stringify` must not emit `#` and receives a defensive `URLSearchParams` copy; resolve omitted `window` after mount while explicit `null` stays local-only; SSR uses normalized initialValue with `isReady: false` and zero History/location access.
- For page-leave hooks (`usePageLeave`): observe window `mouseout` / `mouseover` only; mark left solely when `mouseout.relatedTarget == null` after the observed window has seen at least one `mouseover` since attach (ignore attach/iframe-load spurious leaves); mark entered on `mouseover`; use `Object.is` (or equivalent) guards so repeated leave/enter while already in that state do not re-render; resolve omitted `window` after mount and never fall back when `window: null`; preserve boolean state across disable and window replacement without reseeding `initialValue` (reset the enter-arm flag on window replacement); do not treat blur, visibility, pagehide, unload, touch, or keyboard focus as leave; do not route through `useEventListener` unless proven smaller without semantic loss; keep implementations direct and SSR-safe with `useEffect` only.
- For text-selection hooks (`useTextSelection`): observe `selectionchange` on the selected document only; expose `{ text, rects, ranges, selection }` with package-owned frozen arrays and live native objects; compare text + selection/range identities + rectangle geometry for equality; contain throwing Selection/Range getters; sync once after attach; disable and window replacement clear to empty; cleanup must not call `getSelection()`; never trim selected text; no `useLayoutEffect`.
- For Base64 hooks (`useBase64`): UTF-8 encode without `btoa(unicode)`; encode ArrayBufferView only through the visible byte window; newest generation owns `base64`/`error`/`isLoading`/`promise`; stale success may resolve its caller without state/`onError` updates; keep `execute` stable while disabled; validate MIME/quality; serializer identity alone must not regenerate; SSR stays idle with no auto-encode.
- For debounce-function hooks (`useDebounceFn`): return reactive `isPending` with stable `run`/`cancel`/`flush`; fan out one shared settlement to every caller in a debounce window; normalize invalid delay to `200` and keep zero-delay asynchronous; maxWait and delay must not double-invoke; cancel/flush settle pending callers; option changes while pending cancel using the previous policy; unmount cancels without rejection; latest callback without method churn.
- For event-bus hooks (`useEventBus`): private module registry keyed by string/number/symbol with owner-scoped subscriptions and channel-wide `reset`; emit over a registration-order snapshot; `once` unsubscribes before invoke; collect listener errors and throw after dispatch; prune empty channels; keep controls stable via a latest-key ref synchronized during render (so layout-phase callers cannot target a superseded channel); duplicate same-owner listener registration is idempotent with first-registration-wins `once` mode; no React state from emit; no subscribe/emit during render (controls are no-ops until the mount effect); document realm/package-copy and SSR cross-request limits.
- Document honest lifecycle limits: observer hooks are not replacements for React effect cleanup when the observing component itself unmounts.
- Provide runtime behavior tests and compile-time type tests for public hooks.
- Preserve TypeScript generics and reject incorrect element/ref types instead of widening. Prefer `Element` over `HTMLElement` when SVG and other element subtypes are in scope.

When architecture, conventions, API behavior, package usage or testing policy changes, update this skill if its instructions become stale.
