# Testing

- Use Vitest + jsdom + Testing Library (`react`, `user-event`, `jest-dom`) for unit tests (`--project=unit`).
- Filenames: `name.test.ts`, `name.test.tsx`, `name.type-test.ts` only for package unit/type tests.
- Prefer behavior-focused tests; avoid implementation-detail assertions and brittle snapshots.
- Colocate hook runtime tests and type tests next to the hook implementation.
- Type-test files must be typechecked, excluded from `dist`, and omitted from the npm tarball.
- Cover SSR/import safety for hooks that touch browser APIs in effects, including console warning/error assertions for layout-effect SSR messages when relevant.
- For keyboard hooks, prefer real DOM `KeyboardEvent` dispatch; spy only for registration/cleanup assertions. Assert `event.repeat` / dedupe and filter behavior without arbitrary sleeps.
- For `useEventListener`, cover native inference with type tests (including negative cases), listener option lifecycle (`once`, `signal`, capture/passive), event-name normalization/churn, and SSR omitted-window safety.
- For long-press hooks, use Vitest fake timers deterministically and always restore real timers. Dispatch real `PointerEvent`s with explicit `pointerId` / coordinates. Cover delay normalization, movement cancellation, release metrics, blur/cancel/disable cleanup (no `onRelease`), StrictMode listener/timer uniqueness, and SSR import safety. Storybook browser tests may use short known delays with `waitFor` instead of unexplained arbitrary sleeps.
- For typing-intent hooks, cover default ASCII alphanumeric acceptance/rejection, modifier/repeat/composition filtering, editable focus protection (input/textarea/select/contenteditable/shadow), custom validator and detector freshness without listener churn, enabled lifecycle, StrictMode single active listener, SSR import safety, and focus-activation demos without asserting unreliable synthetic character insertion.
- For media-device hooks, mock `navigator.mediaDevices` deterministically (never request real hardware in unit tests or automated Storybook play flows). Cover support detection, enumeration, grouping, `devicechange`, refresh/permission success and failure, track `stop()` cleanup, async races with deferred promises, enabled lifecycle, automatic `requestPermissions` transitions, and SSR empty unsupported state. Live-hardware Storybook play tests may assert UI only — never click Allow / `ensurePermissions`.
- For `useDisplayMedia`, unit tests and Storybook play tests must never call the real `getDisplayMedia`. Mock `navigator.mediaDevices.getDisplayMedia` with deferred promises for loading/race coverage, and cover support detection, default/custom constraints, track `ended` handling (including stale-track races), stream replacement stopping prior tracks, error normalization (`NotAllowedError`/`AbortError`/`NotFoundError`/`NotReadableError`/generic), declarative `enabled` lifecycle, StrictMode ownership, and SSR-safe idle rendering. The one Live screen-sharing story's play test asserts UI only and never clicks start.
- For `useUserMedia`, unit tests and Storybook play tests must never call the real `getUserMedia` except the single Live camera story's UI-only play test (never click Start). Mock `getUserMedia` with deferred/overlapping promises; cover support sync after mount, default video-only constraints, atomic `start` replacement vs `restart`, deep `autoSwitch` signatures, track-ended partial/final cleanup, imperative/declarative origin, error normalization, Strict Mode ownership, and SSR idle unsupported state.
- For `useWebSocket`, unit tests must install a deterministic native-like WebSocket mock and use Vitest fake timers for reconnect/heartbeat coverage (always restore real timers; keep microtasks real when testing async Blob heartbeat matching). Cover generation ownership, stale-event rejection, explicit vs unexpected close, buffer FIFO/flush/clear boundaries, semantic URL/protocol equality, heartbeat response consumption (exact strings, byte-equal ArrayBuffers, async byte-equal Blobs), pong-timeout winning over late Blob comparisons, Strict Mode single owned connection, and SSR idle closed state without construction. Storybook automated stories must not open real external sockets; the Live connection play test stays idle-only.
- For `useLocalStorage` / `useSessionStorage`, clear namespaced keys between tests; cover writeDefaults, serializers, malformed fallback, mergeDefaults, setValue/remove/reset, same-document registry sync, native storage-area filtering, listenToStorageChanges off, dynamic key/window/null window, Strict Mode, SSR default-first safety, local/session isolation, and pre-ready mutation races (layout-phase controls must not be overwritten by later init). Shared engine helper/registry tests live under `browserStorage/`. Storybook play tests must namespace keys, clean both storage areas when demonstrating isolation, restore mocks, and never place secrets in examples.
- For `useCookies`, clear namespaced cookie tokens between tests (`rh_uc_…` style — cookie names cannot contain `:`); cover parsing/encoding, attributes, get/getAll/set/remove/refresh, dependency filtering, auto dependencies, same-document registry, Cookie Store structural events, shared polling with fake timers, null/custom documents, Strict Mode, SSR `initialCookies`, and pre-ready set/remove/refresh ownership. Storybook play tests must remove cookies with matching path/domain, restore document/timer/cookieStore mocks, and never place secrets in examples.
- For `useJwt`, cover valid decoding (including Unicode), token structure, strict Base64URL/UTF-8/JSON object rules, independent header/payload failures, fallback identity, `onError` effect lifecycle with token-aware + semantic-signature Strict Mode dedupe (invalid A → invalid B with the same error shape must notify; same-token rerenders and callback identity changes must not), multi-instance isolation, throwing-callback containment, memoization without browser resources, and SSR (`onError` not called; `errors` available). Helper tests should exercise private Base64URL/UTF-8/segment helpers without exporting them. Never place full tokens or production-looking secrets in error messages, snapshots, or Storybook output.
- For `useNProgress`, use Vitest fake timers for trickle/completion/removeDelay coverage and always restore real timers. Cover helper normalization (including zero-delay rejection for `speed`/`trickleSpeed` and `removeDelay: 0`), manager registry ownership (WeakMap document → parent map, empty-channel prune, one shared style per document, peg inside bar, independent parent channels, no parent style mutation), slowest-owner aggregation (completing owner at `1` must not force the shared bar to `1` while another owner remains), presentation-owner fallback, restart-during-completion resetting to minimum, declarative transitions (`undefined`/`null`/finite/`NaN`/`Infinity`, number→undefined keeps owner), Strict Mode single effective owner, and SSR idle no-DOM behavior. Storybook browser tests must keep bars in contained custom parents (never leave body-level bars/styles/timers), mount-gate auto-activating demos, assert Show/Hide + Copy + non-empty Shiki output, and run a11y at error level with textual loading state alongside the bar.
- For `useQRCode`, mock `qrcode.toDataURL` with deferred promises for lifecycle/race/error coverage while keeping at least one real-encoder integration path (helper encode or unmocked import). Cover named and default-wrapped module resolution via `resolveQrToDataURL`, automatic vs manual generation, empty (`''`) vs whitespace (`' '`) clearing, exact text preservation, option mapping without mutation, validation failures without encoder calls, newest-generation ownership, stale success returning the produced URL without state/`onError` updates, Strict Mode discarded work, stable `generate`, equivalent-option signature equality, distinct invalid signatures that share an error message, and SSR idle state via the packed React 18 consumer. Storybook browser tests must use real generated images, assert data-URL prefixes and loading/error text, never require camera scanning, assert download attributes without clicking download, keep payloads fictional, and assert Show/Hide + Copy + non-empty Shiki with a11y at error level.
- For `useFavicon`, cover helper URL/rel normalization, matching-link selection (last match), snapshot/restore (including absent/empty href and created-link removal), registry ownership (acquire/update/release, current vs non-current, equivalent updates that preserve order, persist vs restore, document/`rel` isolation, failed-acquire rollback), controlled icon/`enabled`/`null`/`''` lifecycles, external removal without resurrection, dynamic documents, Strict Mode with generation-guarded persist microtasks, equality guards, error containment (including throwing restore/`onError`), and SSR idle via the packed React 18 consumer. Storybook browser tests should prefer isolated iframe documents, assert real `<link>` href changes, restore preview-document stories before finishing (try/finally), clean up iframes/favicon state after persistent demos, and assert Show/Hide + Copy + non-empty Shiki with a11y at error level.
- For `useEyeDropper`, install a deterministic native EyeDropper mock with deferred promises; cover structural support (including null/custom window), synchronous constructor/`open` ordering before any await, initialValue/reset races, cancel→immediate-reopen (stale AbortError/failure must not clear the newer `isPicking`/error/`onError`), cancel without `AbortController` still invalidating ownership, external abort bridging with exact listener add/remove counts, cross-realm AbortError detection, `treatAbortAsError`, NotAllowed/InvalidState/Operation/malformed/own-property results, overlapping latest-request ownership including three-attempt orders (stale success may resolve caller string without state update; stale failures resolve `null`), enabled/window/unmount invalidation, Strict Mode (no construct on mount), identical error messages from distinct attempts notifying once each, and SSR idle with zero constructions via the packed React 18 consumer. Storybook: Live native picker play must never click Open; success-demo plays use temporary mock install/uninstall; scenario stories keep mock isolation; assert Show/Hide + Copy + non-empty Shiki, and a11y at error level.
- For `useFullscreen`, install a deterministic document/element fullscreen mock covering standard and WebKit-prefixed families; cover omitted/null/custom targets and documents, mismatch errors, synchronous request ordering before any await, navigationUI mapping, owned exit refusal, toggle against stale React state, change/error events including Escape/external switch, deferred race invalidation, enabled without platform exit, autoExit genuine-unmount vs Strict Mode remount, multiple instances, and SSR idle with zero request/exit calls via the packed React 18 consumer. Storybook: interactive success demos use the real Fullscreen API; play tests install/uninstall a temporary mock; scenario stories that synthesize another-element/external entry keep a persistent mock; Live native play must never click Enter; assert Show/Hide + Copy + non-empty Shiki, and a11y at error level.
- For `useUrlSearchParams`, cover helper extraction/rebuild for `history`/`hash`/`hash-params` (including `#foo=bar` as route-only in hash mode and `#?…` delimiter stripping in hash-params), delimiter and hash-route preservation, immutable/prototype-safe snapshots, input normalization, nullish/falsy filters, equality, custom stringify `#` rejection, registry subscribe/publish/writer exclusion/mode+window isolation/throwing peers, rapid sequential mutations, concurrent-writer URL rebase, popstate/hashchange without initialValue resurrection, external History + `refresh()`, failed-write atomicity, enabled/local-edit/re-enable, dynamic mode/window/null window, Strict Mode without mount writes, and SSR initialValue-only via the packed React 18 consumer with zero History writes. Storybook browser tests must use isolated same-origin iframe windows (never mutate manager/preview routes), label demo-trail navigation honestly (not as native Back/Forward), clean fixtures after play, and assert Show/Hide + Copy + non-empty Shiki with a11y at error level.
- For `usePageLeave`, dispatch deterministic native `mouseout` / `mouseover` fixtures (never move the real system cursor). Cover `relatedTarget == null` leave vs internal relatedTarget, **ignore leave until after the first mouseover** (iframe attach spurious mouseout regression), mouseover re-entry, render-churn guards, blur/visibility/pagehide/beforeunload/touch/keyboard exclusions, enabled attach/detach with state preservation, omitted/explicit/null/custom iframe windows, window A→B stale-event isolation, Strict Mode single listener pair, multi-instance independence, and SSR render-to-string with no listeners/`useLayoutEffect` warnings. Storybook browser tests must observe isolated iframe `contentWindow`s (never the manager document), arm leave with enter before asserting leave, clean iframes in try/finally, assert leave/re-enter + snapshot + disclosure/Copy/Shiki, and run a11y at error level.
- For `useTextSelection`, use deterministic Selection/Range/DOMRect mocks (do not rely on jsdom geometry). Cover empty/collapsed/multi-range/rect flattening, Unicode/whitespace preservation, throwing getters, equality guards, enabled/null/dynamic window, stale old-document events, Strict Mode, cleanup without `getSelection`, and SSR empty snapshots. Storybook may patch selection fixtures and must restore in `finally`.
- For `useBase64`, cover UTF-8/emoji, ArrayBufferView offsets, Blob/canvas/image paths, serializer validation, generation ownership/stale races, enabled/manual execute, and SSR idle. Prefer small synthetic bytes; never load remote images or encode secrets in Storybook.
- For `useDebounceFn`, use Vitest fake timers; cover delay/maxWait races, caller promise fan-out, cancel/flush settlement, option-change cancel policy, latest callback, Strict Mode, and SSR with no timers until `run`. Storybook plays must use short deterministic delays.
- For `useEventBus`, cover key isolation (string vs number), owner duplicate vs multi-owner, once/nested emit, reset during emit, error aggregation, key change + stale stops, channel pruning, zero rerenders from emit, and SSR no-subscribe-on-render. Storybook examples must not claim cross-tab/network/persistence.
- For `useElementByPoint`, unit tests (jsdom) must stub `document.elementFromPoint` / `document.elementsFromPoint` and the owning window's `requestAnimationFrame`/`cancelAnimationFrame` explicitly — jsdom does not implement real hit testing or layout, so coverage there is about the hook's own scheduling/state logic (generation-based stale-frame cancellation, pause/resume freezing, `enabled` lifecycle, `multiple` mode switching, custom-`document` resolution, SSR import safety), not real geometry. Storybook browser tests run in a real browser (Playwright) and must instead rely on genuine layout: read real target coordinates via `element.getBoundingClientRect()` (or dispatch real pointer events with `clientX`/`clientY`), and assert against the hook's actual detected element rather than re-stubbing `elementFromPoint`. Use `waitFor` for the `animationFrame` scheduler's rAF-batched updates instead of arbitrary sleeps; `sync`-scheduler assertions may still use `waitFor` for consistency. When testing `update()` against a CSS-only position change, drop any CSS transition/animation on the moved target (or wait for it to finish) so `getBoundingClientRect()` reflects the final position deterministically instead of a mid-transition value.
- For `useElementHover`, unit tests must use Vitest fake timers for delay coverage and dispatch native `mouseenter`/`mouseleave` on the target (they do not bubble — do not rely on `mouseover`). Cover opposite-transition cancellation, enabled lifecycle, target replacement/null resets, optional removal observation (including async `MutationObserver` callbacks with `await act(async () => Promise.resolve())`), timer generation guards, listener ownership under Strict Mode, and SSR import safety. Storybook browser tests should use `userEvent.hover()` / `userEvent.unhover()` with short documented test delays (or a hidden browser-test story) instead of repeated one-second sleeps.
- For `useFocus`, unit tests must assert `ownerDocument.activeElement`, native `focus`/`blur` listeners, imperative `focus({ preventScroll })`, initial-focus idempotence, `:focus-visible` conservative matching, enabled lifecycle without forced blur, cross-document iframe targets, and SSR/hydration safety. Storybook browser tests should scope assertions to the canvas, use explicit mount toggles for initial focus, and avoid auto-focusing Docs mode on load.
- For `useFocusWithin`, unit tests must assert native `focusin`/`focusout` listeners, owning-document containment, descendant focus movement without false flicker, null-`relatedTarget` microtask reconciliation with generation guards, enabled lifecycle without forced blur, portal exclusion, cross-document iframe targets, and SSR/hydration safety. Storybook browser tests should verify the primary form example status strings, field-to-field transitions, and outside-focus false state without arbitrary sleeps.
- For `useInfiniteScroll`, unit tests must stub scroll metrics (jsdom has no real layout), cover all four directions, distance normalization, serialized async loading, error normalization, `canLoadMore`, no-progress protection, `check()`/`reset()`, Window/Document targets, ResizeObserver attach/disconnect when available, Strict Mode cleanup, and SSR idle safety. Storybook browser tests should scroll the primary infinite list near the bottom, confirm batch growth, reach the maximum via `canLoadMore`, and verify Reset without arbitrary long waits.
- For `useMouse`, unit tests must dispatch deterministic `MouseEvent` / synthetic touch events with explicit page/client/screen/movement fields, cover built-in and custom extractors, `eventFilter` delayed/stale invocation guards, page-scroll recalculation via mocked scroll offsets, touch reset on final touchend/cancel, target ref synchronization, enabled lifecycle, Strict Mode listener uniqueness, and SSR initial-value safety. Storybook browser tests should move within a contained surface and assert source/coordinate relationships rather than fragile absolute page literals when layout offsets vary.
- For `useMousePressed`, unit tests must dispatch deterministic mouse/touch/drag events, cover global release outside element targets, multi-touch remaining-touch behavior, mousedown+dragstart single transition, administrative resets without callbacks, temporary release listener attach/detach, capture lifecycle, target replacement, enabled lifecycle, callback throw cleanup, and SSR initial-value safety. Storybook browser tests should press inside a pad, release outside, and assert pressed/source transitions without relying on keyboard activation.
- For `useParallax`, unit tests must mock `getBoundingClientRect` and dispatch deterministic `mousemove` / synthetic `deviceorientation` events, cover center/corner normalization, zero-size targets, screen-angle rotation (`0/90/180/270` and negative equivalents), source switching without treating API presence as activation, adjuster inversion/sensitivity/throw/non-finite containment, clamp true/false, target/enabled lifecycle, Strict Mode listener uniqueness, and SSR centered mouse-fallback safety. Storybook browser tests should move within a scene, assert roll/tilt signs, simulate orientation without native permission prompts, and verify layered transforms differ by depth.
- For `useScroll`, unit tests must stub scroll metrics with mutable `scrollLeft`/`scrollTop` setters (jsdom has no real layout), cover helper normalization/comparators, LTR and RTL arrived-state math, coalesced measure scheduling, Window/Document/element targets, throttle leading/trailing and idle/onStop timing with fake timers, imperative `scrollTo`/`setX`/`setY` auto-behavior sync, `measure()` identity and direction reset without callbacks, enabled lifecycle preserving position, target replacement, mutation observation when `observe: true`, listener-option churn resetting `isScrolling` without `onStop`, Strict Mode single listener, and SSR idle safety. Storybook browser tests should scroll contained surfaces, assert position/arrived/direction updates, exercise setX/setY and measure controls, and gate window/document iframe demos behind onLoad + enabled — use `waitFor` instead of arbitrary sleeps.
- For `useScrollLock`, unit tests must assert inline `overflow: hidden` application, exact overflow restore (including `!important`), WeakMap multi-owner acquire/release, Window/Document scroll-root resolution, requested `isLocked` vs shared ownership, target replacement/null/unmount cleanup, `initialLocked` mount-only seeding, stable `lock`/`unlock`/`toggle`, Strict Mode ownership, and SSR with no style writes. Storybook browser tests should lock/unlock contained scrollers, keep page-lock demos in isolated iframes, finish unlocked/clean, and use `waitFor` instead of arbitrary sleeps.
- Storybook interaction and accessibility checks run through `npm run test:storybook` (`--project=storybook`).
- CI workflows that run Storybook browser tests, `test:reset`, or `test:layout` must install Playwright browsers after `npm ci` (`npx playwright install --with-deps chromium`). npm does not download browser binaries automatically.
- Static Storybook layout overflow audit: `npm run build:storybook && npm run test:layout` (`scripts/storybook-layout-audit.mjs`, Playwright against `storybook-static/index.json`, every public `Hooks/*` story unless tagged `layout-audit-skip`). Internal/layout stress coverage also lives in `src/stories/layout/LongContentStress.stories.tsx` with `assertNoPageOverflow` / `assertPanelContained`.
- Browser-level reset-after-play audit: `npm run build:storybook && npm run test:reset` (`scripts/storybook-reset-audit.mjs`) proves remount after play for a representative stateful matrix, the intentional errored fixture (`Internal/Layout/Errored play reset`, tagged `!test`), and a story-switch stale-reset race. Unit coverage remains in `.storybook/resetAfterPlayDecorator.test.tsx`.
- React 18 packed-consumer SSR checks run through `npm run test:ssr:react18` and are part of `verify:ci` (not every unit-test run) because they install React 18 into a temporary directory.
- Setup lives in `vitest.setup.ts` (unit) and `.storybook/vitest.setup.ts` (Storybook).
- Coverage via `npm run test:coverage` covers library source only.
- Release safety: `npm run validate:release` (`scripts/validate-release.mjs`) asserts package metadata, tarball allowlist, workflow token-free publish constraints, and public export keys. Dist allowlist/export checks are skipped when `dist/` is absent (unit tests run before `build:lib` in `verify`); use `--require-publishable` after a library build (CI/publish). Unit coverage lives in `src/test/validate-release.test.ts`.

When architecture, conventions, API behavior, package usage or testing policy changes, update this skill if its instructions become stale.
