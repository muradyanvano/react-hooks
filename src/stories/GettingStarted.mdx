<section className="space-y-3">
  <h2 className="text-xl font-semibold">Limitations</h2>
  <ul className="list-disc space-y-2 pl-5 text-sm leading-7 text-slate-600">
    <li>Twenty-seven public hooks exist in this prerelease.</li>
    <li>
      <code>useOnClickOutside</code> supports a single ref, no ignore lists, and
      no iframe-specific helpers.
    </li>
    <li>
      <code>useOnElementRemoval</code> is not a replacement for React effect
      cleanup when the observing component itself unmounts.
    </li>
    <li>
      <code>useOnKeyStroke</code> does not parse combination strings; use a
      predicate for modifiers. It does not auto-ignore editable fields.
    </li>
    <li>
      <code>useEventListener</code> supports one target per call and returns{' '}
      <code>void</code>. Evaluating <code>document</code> as an argument is not
      intrinsically SSR-safe.
    </li>
    <li>
      <code>useOnLongPress</code> is Pointer Events only, does not suppress
      clicks, and must not be the sole path for essential actions.
    </li>
    <li>
      <code>useOnStartTyping</code> defaults to ASCII alphanumeric keys, uses{' '}
      <code>keydown</code> (not IME reconstruction), and does not prevent
      default.
    </li>
    <li>
      <code>useDevicesList</code> lists devices only, stops temporary permission
      tracks immediately, and treats <code>permissionGranted</code> as
      hook-local state.
    </li>
    <li>
      <code>useDisplayMedia</code> owns captured streams, stops tracks on stop /
      unmount / browser-ended sharing, and recommends imperative{' '}
      <code>start()</code> from a user gesture.
    </li>
    <li>
      <code>useElementByPoint</code> only accepts client (viewport) coordinates,
      does not poll for layout changes (call <code>update()</code> explicitly),
      and requires any custom <code>document</code> to already exist and be
      same-origin-accessible.
    </li>
    <li>
      <code>useElementHover</code> tracks mouse hover only — not touch, keyboard
      focus, or CSS <code>:hover</code>. Provide accessible alternatives for
      hover-only information.
    </li>
    <li>
      <code>useFocus</code> tracks direct focus only — not descendant
      focus-within. Disabling resets hook state without blurring the browser
      element. Use initial focus carefully in Docs mode.
    </li>
    <li>
      <code>useFocusWithin</code> tracks DOM containment only — React portals
      outside the subtree do not count. It does not move or trap focus.
    </li>
    <li>
      <code>useInfiniteScroll</code> is scroll-metric based. Consumers own
      fetching, item state, and scroll anchoring for top/left layouts. Provide
      accessible alternatives for long feeds.
    </li>
    <li>
      <code>useMouse</code> tracks mouse and optional touch events, not unified
      Pointer Events. Element-relative coordinates require a custom extractor.
      High-frequency updates may need <code>eventFilter</code> throttling.
    </li>
    <li>
      <code>useMousePressed</code> exposes one aggregate boolean lifecycle, not
      button state, touch count, or keyboard activation. Release is observed
      through the owning window.
    </li>
    <li>
      <code>useParallax</code> returns values only — it does not write CSS,
      request orientation permission, or smooth sensor noise. Consumers own
      transforms and reduced-motion behavior.
    </li>
    <li>
      <code>useScroll</code> is scroll-metric based. Imperative{' '}
      <code>smooth</code> scroll does not auto-sync state — call{' '}
      <code>measure()</code> or wait for scroll events. After imperative{' '}
      <code>ref.current</code> assignment, a later React commit is required
      before attachment.
    </li>
    <li>
      <code>useScrollLock</code> applies inline <code>overflow: hidden</code>{' '}
      only — it does not suppress scroll events or act as a focus trap. Multiple
      owners share one lock; overflow restores when the final owner releases.
    </li>
    <li>
      <code>useUserMedia</code> prefers imperative <code>start()</code> from a
      user gesture. Default <code>enabled</code> is false. It owns acquired
      streams and does not record, upload, or analyze audio levels.
    </li>
    <li>
      <code>useWebSocket</code> constructs sockets only in effects. Explicit{' '}
      <code>close()</code> never auto-reconnects. <code>autoClose</code> only
      controls <code>beforeunload</code> — React unmount always releases
      ownership. Heartbeats are application messages, not native ping frames.
    </li>
    <li>
      <code>useLocalStorage</code> reads storage only after mount. Malformed
      payloads fall back locally without auto-deletion. <code>remove()</code>{' '}
      deletes; <code>reset()</code> writes defaults. Do not store secrets — this
      is persistence, not encryption.
    </li>
    <li>
      <code>useSessionStorage</code> matches that control surface for{' '}
      <code>sessionStorage</code>. It survives reloads in the same browsing
      context but is not a durable cross-tab store.
    </li>
    <li>
      <code>useCookies</code> cannot read or create <code>HttpOnly</code>{' '}
      cookies. Deletion needs matching path/domain. Assignment success is not
      acceptance proof. SSR reads require explicit <code>initialCookies</code>.
    </li>
    <li>
      <code>useJwt</code> decodes only. It does not verify signatures or prove
      claims are trustworthy. Never authorize from client-side decoded claims
      alone. <code>exp</code>/<code>nbf</code>/<code>iat</code> are NumericDate
      seconds. Use only synthetic tokens in examples.
    </li>
    <li>
      <code>useQRCode</code> generates image data URLs only. Scanning does not
      validate or trust destinations. Capacity depends on version, encoding, and
      error-correction. Quiet zone and contrast matter for scan reliability. The
      package depends on <code>qrcode</code> for encoding. Use only synthetic
      payloads in examples.
    </li>
    <li>
      <code>useFavicon</code> updates document head metadata only. Browser tab
      icons may cache or delay. It does not generate badges, resize images,
      manage manifests, or guarantee immediate UI refresh. Prefer isolated
      iframe documents in Storybook demos. Consumers own accessible in-page
      status text.
    </li>
    <li>
      Storybook here is local documentation, not a deployed docs site yet.
    </li>
  </ul>
</section>
